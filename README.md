# 哥伦布手机套餐横向对比

美国俄亥俄州哥伦布市（Columbus, OH）手机资费的严谨横向对比。**10 个品牌 / 50 个套餐档位**，
覆盖单线自带手机（BYOD）、多线拼卡、合约购机三种场景。

成品是一个**完全自包含的单文件 HTML**，双击即开，无外部依赖、无网络请求：

> [`Columbus_手机套餐对比_2026-08-14.html`](Columbus_手机套餐对比_2026-08-14.html)

价格口径日期：**2026-08-14**。全部数据来自当天对各运营商官网的实际抓取。

---

## 这份东西解决什么问题

美国手机资费的横向对比几乎全是错的，因为**大家在拿不可比的数字排名**：

- 有的品牌标价含税，有的另计——俄亥俄的税费在低价档能吃掉 **40%**；
- 有的报 AutoPay 折后价，有的报折前价；
- 首月促销价被当成常规价；年付摊算价被当成月付价；
- 「无限」至少有五种互不相同的含义。

所以这份对比的地基是一个换算：把所有价格拉平成**到手价**（你银行卡实际被扣的数字），再排序。

### 到手价换算公式（俄亥俄 / 哥伦布）

```
到手价 = 广告价 × 1.2359 + 每线固定费 + $0.25
```

| 项 | 值 | 说明 |
|---|---|---|
| 政府税费 | **23.59%** | 州+地方 9.20% + 联邦 USF 14.39% |
| 每线固定费 | Verizon `$3.99` / AT&T `$4.99` / T-Mobile `$4.49` | **不是税**，是运营商自收费；不受任何价格锁保护 |
| NG911 | `$0.25`/线/月 | 俄亥俄州固定额 |

**倍率随档位递减**（固定费不随价格缩放）：`$25` 档 ×1.45、`$50` 档 ×1.34、`$90` 档 ×1.29。
不存在单一的「×1.3」——套餐越便宜，税费咬得越狠。

> **一处对权威数据的修正**：Tax Foundation 2025 版给俄亥俄的合计税率是 22.56%，但它用的是 2025 年三季度的
> 联邦 USF 缴费系数（36.0%）。FCC 已于 2026-06-15 核准 Q3 2026 系数为 **38.8%**（历史最高）。
> 按 38.8% × 37.1% 安全港 = 14.39%，俄亥俄实际应为 **23.59%**。直接抄 Tax Foundation 会低估约 1 个百分点。

换算的效果很直接：**同样标价 $25，Cricket / Total Wireless / Visible / Metro / US Mobile 到手就是 $25，
而 AT&T 预付费到手 $33.78。** 这个差距在原始报价表里完全看不出来。

## 数据保鲜：哨兵 + 保鲜度层

价格会变，而这份东西是静态的。所以配了两层机制，让它**永远不会假装自己是最新的**。

### 保鲜度层（页面内，零维护）

页面右上角有个徽章，**在你打开页面的那一刻**用口径日期和当天日期算出数据有多旧：

| 状态 | 阈值 | 表现 |
|---|---|---|
| 🟢 | ≤ 30 天 | `数据 N 天前核对` |
| 🟡 | 31–90 天 | 变黄，提示促销价大概率已变 |
| 🔴 | > 90 天 | 变红，**并在页面顶部插入一个警示框**，明说「请当作历史参考，不要直接拿去下单」 |

每个套餐档位展开后，底部也会写明 `2026-08-14 抓取 · 出处：<官方链接>`，一键跳去核对。

### 变更哨兵（GitHub Actions，每周一次）

`.github/workflows/price-watch.yml` 每周一 13:00 UTC 跑一次
（也可以在 Actions 页面手动触发），抓 **18 个官方页面**，
一旦价格文本变了就**自动开一个 issue**，附上人能读的 diff：

```diff
- $25 /mo
+ $22 /mo
- First month $30, then $20/mo after.
```

#### 三个刻意的设计取舍

1. **只检测「变了没有」，不解析「现在多少钱」。**
   给每家写定向价格解析器很脆——页面一改版就静默失效，然后自信地写入错误数字。
   **错数字比过期数字更糟**，所以宁可只报「这里动了，你自己看」。

2. **抓不到 ≠ 变了。** 403 / 超时 / DNS 失败一律单独归类为「无法核实」，
   绝不当成变更，也绝不覆盖上次的 baseline。
   Mint 与 US Mobile 有间歇性反爬（同一天两次请求可能一次 200 一次 403），
   把它们留在清单里是**故意的**：从 403 变成 200 本身就是信号，也防止我们默默忘掉这两家。

3. **AT&T 的分档价是客户端渲染的，静态抓不到。**
   所以主信号源用的是 AT&T 自己发布的机器可读规格页
   `att.com/ai-instructions/build-a-plan.html`（静态、含完整价目矩阵，89 条价格片段）。
   `att.com/plans/wireless/` 只能拿到营销语「starting at $30」，作为辅助保留。

#### 误报控制

上线前做过验证：建立基线后**立刻重跑一次，17/17 可访问页面零变更**——
说明轮播文案、A/B 测试之类不会造成每周刷屏。仍可能误报的来源：
营销文案调整、地区化差异、页面改版。**真实降价一定会出现在报告里，但不是每条都值得动。**

收到 issue 后的处理流程：扫一眼 diff → 判断是不是实质变动 →
是的话让 Claude 重跑完整分析、更新 `src/data_*.py` 并重新 `build.py`。

```bash
python3 watch/watch.py          # 本地手动跑一次
python3 watch/watch.py --init   # 重建基线（换了监控清单后用）
```

`watch/watch.py` 同样**只用 Python 标准库**，没有 pip 依赖——依赖越少越不容易烂。

### 为什么不做「真·实时」

做不到，而且不是技术偷懒：

- **没有官方 API。** 运营商不提供任何价格 feed。
- **浏览器端拿不到。** 静态页面直接 `fetch('att.com')` 会被 CORS 挡死；
  发布到 claude.ai 的 Artifact 运行时也只有 `downloads` / `mcp` 两项能力，
  `mcp` 只能调用你自己已连接的连接器——不存在「运营商资费」这种连接器。
- **服务端抓取很脆。** 实测就遇到 Mint / US Mobile 反爬、AT&T 需要伪装 UA、
  Spectrum 超时、Akamai 拦截、Ookla 与 Reddit 整站不可达、Metro 的国家清单是动态组件抓不出来。
- **最根本的一条：运营商没有「一个价格」。**
  价格随地址、登录状态、是否携号转入、设备、AutoPay、付款方式、宽带绑定动态变化。
  就算抓到了，那也只是某个匿名会话在某一刻看到的某个值——
  拿它冒充「实时价格」比标一个诚实的过期日期更有害。

## 重建

```bash
python3 src/build.py
```

输出到仓库根目录。也可以指定路径：

```bash
python3 src/build.py ~/Desktop/输出.html
```

只需要 Python 3 标准库，无第三方依赖。

### 文件职责

| 文件 | 作用 |
|---|---|
| `src/build.py` | 渲染主程序：到手价计算、各章节 HTML 生成 |
| `src/tpl.py` | CSS + 页面骨架 + 交互 JS（价格轴泳道排布、同价位匹配） |
| `src/data_plans.py` | 10 个品牌 50 个套餐的逐档数据 |
| `src/data_extra.py` | 税费模型、多线定价、设备补贴、本地覆盖 |
| `src/data_audit.py` | 体检结论、推荐排序、落选名单、锐评 |

**价格会变。** 要更新时改数据文件重跑 `build.py` 即可，不用碰渲染逻辑。
但税率、USF 系数、运营商自收费同样会变（AT&T 的管理费八个月内涨了两次），重做时都要重新核。

## 方法与可信度

- 全部价格来自 **2026-08-14 当天**对官网的实际抓取，不使用任何记忆中的数字。
- 严格区分三种价格：常规牌价 / AutoPay 折后价 / 限时或条件促销价。促销价单列并标注失效日，**不参与主排序**。
- 严格区分**官方点名**与**第三方推断**。例如 Cricket 官方点名 AT&T、Visible 与 Total Wireless 官方点名 Verizon，
  这三家可以当事实写；而 **Spectrum、US Mobile、Google Fi 三家官网全站不点名任何底层运营商**，
  所有「Warp = Verizon」之类的映射都只能标为第三方推断。
- **查不到就写「未找到」，绝不推测填空。** 页面第 11 节列出了全部未能核实的字段。

### 已知的空缺

- Total Wireless 的非 AutoPay 牌价（官网只印 AutoPay 价）
- Total 的 200+ 国际目的地清单是否含中国大陆（页面动态加载，未渲染）
- US Mobile 热点超额后的速度（官网四处均无）
- Metro 的 2/3/5 线官方每线价（查过 7 个官方页面均未刊登）
- Mint Mobile 的网络归属与 50GB 阈值（抓取时返回 HTTP 403，未取得官网原文）
- 论坛口碑（Reddit 在抓取环境中全程不可访问，因此页面内**不含任何论坛传闻**）

## 免责

这不是理财或消费建议，也不能替代你自己在结账页的核对。运营商页面会按地址、登录状态、是否携号转入、
设备、AutoPay、付款方式和宽带绑定动态变化——**下单前必须在结账页再确认一次总价**。

到手价是估算，误差带 **±3~6 个百分点**，最大误差源是联邦 USF 的安全港口径。

覆盖是逐街区的事：都会区级别的路测和 FCC 面积覆盖**不能**替代你在住处、教室、办公室和通勤路线上的实测。
